What is being compared

There are 19 folds. Each hides one dataset from the agent's reference material, hands it that dataset's raw files, and asks it to harmonize them. We compare the result against what a domain expert produced for the same dataset.

The reference

bervodata.watershed_sfa_soil_moisture.ddt_soil_moisture_observation — 6.4M rows covering all 19 datasets. This is the expert's own harmonized output loaded into BERDL, so it is a complete reference rather than the 49-row snippets kept in the repo. Its 19 dataset identifiers map one-to-one onto the 19 fold targets.

Three translations applied first

Each would silently corrupt the comparison if skipped:

IssueTranslation
Water potential stored in pascals, schema says kPadivide by 1000
site_id is not a column — it is embedded as <dataset>__<site>join to sdt_location.site_identifier
Dataset IDs use _ in the repo, - in the lakehousenormalise separators
What "correct" means here. The reference is one expert's work, not an independent second opinion. These metrics measure agreement with that expert. Where the two disagree, the expert is treated as right by convention — occasionally the agent may be defensible and the convention merely different.

Batch: 19 runs from main@ba049e7, all completed, $101.90 total. Scored 19/19 with no failures.

The primary measurement: output equivalence

The central question is simple — did the agent produce the same table the expert did? The complication is deciding when two rows are "the same row".

The obvious answer is to match rows agreeing on timestamp, site, depth and replicate. That turns out to be badly misleading: if the agent writes site ER-WML1 where the expert writes ER-WML1_HERB, nothing matches and the score is zero even when every number is right. A uniform clock offset does the same thing. So we measure at four levels of strictness and report all four.

LevelRows match when they agree on…What it isolates
L0nothing — distributions onlyunit errors, gross row-count errors
L1timestamp + depth + replicateare the values right, ignoring site naming?
L2L1 + site, after translating expert names into the agent's vocabularyis site identity recoverable?
L3all four, exactlythe strict, conservative headline

What is reported at each level

  • Recall — of the expert's rows, how many did the agent reproduce?
  • Precision — of the agent's rows, how many correspond to an expert row? Below 1 usually means rows the expert filtered out were kept.
  • Cell agreement — among paired rows, what fraction of individual values match? Numbers within a small tolerance; text exactly.
  • Null-mask agreement — kept separate, because agreement computed only over cells where both sides have a value would hide an agent writing 0 where the expert recorded "missing".
  • Gap structure — not how many rows are missing but which. A whole missing site is a different defect from the same count missing at random.

Timestamps repeat across sites, so keys are not unique. Rows are paired by sorting both sides and matching the n-th occurrence to the n-th — which makes row order irrelevant.

Finding. By the strict measure alone the median fold scores 0.00 — a number close to meaningless. Six of 19 folds exceed 0.95; the rest are dominated by site naming and clock offsets rather than wrong data. The gap between L1 and L3 is the result, not a nuisance.

Reading the ladder — fold 17 worked through

This fold was analysed by hand before the scorer was written, and now serves as the known-answer regression test.

LevelPrecisionRecallCell agreement
L1 — site-blind0.5300.99990.620
L2 — site crosswalked0.3980.7510.951
L3 — strict0.0000.000—

Read together: the agent got essentially every timestamp, depth and replicate right (L1 recall 0.9999), and once site names are reconciled 95% of all values agree. The strict zero decomposes into three separately fixable problems:

  • Site vocabulary collapsed. Expert uses ER-WML1_HERB and ER-WML1_SHRUB; the agent emits only ER-WML1.
  • A row filter was missed. 1.89× the expert's row count and 10 extra sites — the even-numbered plots the expert excludes as warming treatments.
  • Coordinates not resolved. Every site blank and flagged g2 ("unavailable") while the expert resolves 10 of them from a registry the agent's own instructions list.

A single strict score reports "0" for all three indistinguishably. This is the whole argument for the ladder.

Automatic diagnosis: why a fold differs

A score says a fold is wrong; a diagnosis says how. Each fold gets findings carrying the evidence that triggered them. Findings state evidence, not conclusions — "ten sites appear that the expert lacks" is an observation; "the agent forgot a filter" is a hypothesis to be checked against the expert's documented steps.

Finding: the failures are structural, not numerical. 53 findings across 19 folds, and almost all concern which rows and which sites — filters, naming, coordinates, timezones. Not one fold shows a unit-scale or sign error. Six folds have no critical finding at all.

That matters for where to intervene: the arithmetic of unit conversion is solved; the record-selection logic is not.

Timezone offsets — the single largest effect

A uniform clock offset drives every keyed score to zero while leaving all values perfectly correct. When one is detected we re-score with it removed and report both numbers, which answers a specific question: how much of this failure is one systematic mistake rather than many scattered ones?

Fold 18 is the cleanest illustration: 3,204 agent rows against 3,204 expert rows, 534 distinct timestamps on each side, zero overlap — and identical depths, replicates and values. One mistake, total failure by exact match.

Finding. Removing the offset lifts the median strict score from 0.00 to 0.84. Folds 14 and 16 stay at zero, so they have problems beyond the clock.

The detector fires only when timestamps genuinely fail to line up and a candidate shift recovers most of them. A looser earlier rule flagged four already-correct folds on a single coincidental match; both conditions are needed.
6

Schema conformance

Does the output have the right shape? Columns present, no extras, correct order, values inside plausible ranges (volumetric water content 0–1, water potential negative, depth 0–100 m), required fields populated.

What we deliberately do not score: raw pandas dtypes. A CSV has no types — what pandas infers on read is a property of the reader, not the agent. Scoring it would mark every run wrong for storing a timestamp as text. Instead we score coercibility: does every value parse into its intended type without loss?

Note also that the repo's TargetSchema.is_valid() ignores range violations, so a volumetric water content of 95 passes it. Ranges are scored here and count toward the verdict.

Finding. 14 of 19 folds fully conformant. Zero uncoercible values anywhere in the corpus — every emitted value parses as its intended type. Failures are structural (a missing or extra column, an unpopulated required field), not malformed data.

7

Sites and coordinates

The agent also emits a location table. Against sdt_location we measure site set precision/recall/F1, great-circle coordinate error per matched site, and qc_flag accuracy.

The lakehouse has no qc_flag column, but geolocation_resolution_method records how each coordinate was obtained. Mapping that vocabulary onto g1 (from the registry) and g2 (unavailable) makes coordinate provenance scoreable.

The denominator matters: some expert sites have no coordinates at all, so the resolvable count is smaller than the site count and is reported separately.

Finding: when the agent attempts coordinates it is exact; the problem is not attempting.

  • Site set F1: median 1.000 across 19 folds — site discovery is solid.
  • Coordinates comparable on 10 folds: median error 0.0 m, all within 100 m.
  • qc_flag accuracy: median 1.000 (15 folds).
  • But 5 folds report coordinates as unavailable that the registry resolves.

So COORD_UNRESOLVED is a lookup-not-performed failure, not an accuracy failure — a materially different fix.

8

Documentation quality

The agent documents its transformations in prose. Exact text matching is worthless here — the earlier pilot found 0/8 agreement on wording while the executed outputs were identical. But "does the text describe the same operations?" is answerable.

Two different fields

  • unit_conversion is not prose. Its 153 expert values collapse to 9 templates once numerals are masked, so it is parsed deterministically into (factor, from-unit, to-unit) and scored exactly.
  • transformation is reduced to the operations it names from a controlled vocabulary — JOIN, FILTER, RENAME, TIMEZONE, PARSE_DATETIME and so on. We then ask which expert operations are missing from the agent's account.

Three choices worth stating in Methods: steps are pooled per dataset, not per variable group (a filter governing every column is recorded inside the depth group); results are reported stratified and unweighted because FILTER appears twice in 153 patterns yet drives the largest errors; and recall pools the mapping text with notes.md while precision stays attributed per artifact.

Finding: 72 of 83 expert operations are documented, and source-file identification is perfect (median F1 1.000 for payload and location files).

The sharpest observation: the agent states timezone handling in 18 of 19 folds, and still gets the timezone wrong in 5. Saying it is not doing it — these are not knowledge failures but execution failures, which points the fix at the code path rather than the instructions.

Counts, not percentages, for small cells: FILTER occurs once in this corpus, so "1/1" is a case report rather than a rate.

Behaviour and context — not quality metrics

These describe how a run happened. They are covariates and must not be read as quality: a cheap run that silently skips a filter would otherwise look efficient.

  • Exemplar substitution — which expert implementations the agent actually opened, from the access traces. This observes the ablation mechanism directly rather than inferring it from score differences.
  • Cost, turns, tokens, tool mix — context only.
  • Process integrity — a gate, not a score.
  • Difficulty covariates — row count, sites, source files, unit conversions, exemplar pool size. These separate "the agent did well" from "the dataset was easy".

Findings. Cost median $4.69 (range $3.56–13.57), 80 turns median, 3 exemplars read median. Process integrity: 19/19 clean — which is precisely why it is a gate: it has no power to discriminate between runs.

The agent does visibly compensate for ablation: with all six cluster-mates withheld, fold 1 opened four out-of-cluster examples instead.

How to read these statistics

  • The folds are not independent. Six of 19 are the same micrometeorology cluster. Treating n=19 as nineteen independent observations overstates the evidence, and the pre-registered cluster bootstrap resamples only three clusters.
  • There are no error bars. Every fold is a single run. Two accidental repeat runs differed by 3.9% of rows between identical invocations, so run-to-run noise is a real fraction of what is being measured. Per-fold scores are point estimates of unknown precision until a repeat batch exists.
  • The ablation contrast is confounded with dataset type and intrinsic difficulty. Any ablation result here is exploratory.
  • One expert, not ground truth. Disagreement means the agent differs from that expert's conventions.
  • Prose scoring is lexical. Transformation text is matched against a controlled vocabulary by regular expression, applied identically to both sides. An LLM reader would recall more but needs blind, symmetric validation against human annotation first — an LLM judging LLM-written text has a self-preference bias.

For these reasons the results report per-fold detail and effect sizes rather than p-values, and any composite is shown beside its components, never instead of them.

11

What to do next

  • Fix timezone handling. Five folds fail outright on it and the documentation shows the agent knows it should — the highest-yield correction available.
  • Make filtering explicit in the skill. Eight folds retain rows the expert excludes. The instructions cover schema and units well but say little about exclusion criteria.
  • Make the location-registry lookup mandatory. Five folds report coordinates unavailable that the registry resolves — and where the agent does look, it is exact.
  • State a site-naming convention. Several folds differ only in how sites are labelled; cheap to specify, currently costs full credit.
  • Run a repeat batch so per-fold scores acquire error bars.

Reproduce: python -m src.metrics.run_all, then python -m src.metrics.report.
