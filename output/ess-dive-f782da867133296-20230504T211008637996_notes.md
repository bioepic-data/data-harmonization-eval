# Harmonization notes — dataset index 26

- **Dataset identifier:** `ess-dive-f782da867133296-20230504T211008637996`
- **DOI:** doi:10.15485/1671826
- **Title:** Soil bulk density and texture data collected during field survey associated with NEON AOP survey, East River, CO 2018
- **Payload file:** `ER18_soil_physical.csv` (586 rows)

## Inclusion decision

**INCLUDE.** The dataset contains a direct observation of volumetric water
content (`water content %vol`) measured on soil-core samples (Rule 2 satisfied).
It is a machine-readable dated measurement table (Rule 4). No duplication /
superseding package is known in the supplied references (Rule 1). No
experimental manipulation (Rule 3). Minimum-metadata gap is handled via `g2`
(Rule 5, see Location below).

## Payload identification

Only one file is staged in the package workspace, `ER18_soil_physical.csv`,
which is the measurement payload. The package metadata lists additional
distribution items (a documentation zip, a raw-data zip, and the authors'
calculation script `soil_physical_merge_calculate.py`); none are staged here and
none are needed — the CSV already contains the calculated `water content %vol`.

## Measurement type / time series

Discrete sampling campaign (NEON AOP associated field survey, summer 2018), not
a sensor deployment. Each site + depth has a single campaign observation keyed
by a collection date. `is_timeseries = False`.

## Rows dropped / retained

- Source has 586 rows: 159 subsurface (`-SBD50`, 50–55 cm) and 427 surface
  (`-SBD`, 2.5–7.5 cm).
- Volumetric water content was measured on **surface samples only**. All 159
  subsurface rows have a blank `water content %vol` and carry no other moisture
  variable, so they are **dropped** (consistent with the expert pattern of
  retaining only rows with a measured moisture value).
- 2 of the 427 surface rows also have a blank `water content %vol` and are
  dropped. Final harmonized output: **425 rows**.

## Data-quality observations (values retained as-is)

- Three source `water content %vol` values are physically implausible: two
  negative (−5.22, −12.31 %vol) and one above 100 (104.03 %vol). These appear to
  be computation/measurement artifacts in the source. They are retained as
  computed (−0.0522, −0.1231, 1.0403 m³ m⁻³) rather than silently dropped;
  downstream QC may wish to filter them.
- One surface row (`site_id = 432-ER18`, `SampleID = 431-ER18-SBD`) has a valid
  water-content value but blank `Collection date` **and** blank Top/Bottom depth
  in the source. It is retained with `datetime_UTC` and `depth_m` left empty and
  `replicate` empty; no values were invented.

## Location resolution (qc_flag)

- **No per-site coordinates are available** in the payload, in any package
  ancillary file (none staged), or in the cached ESS-DIVE metadata. The metadata
  provides only a watershed-level bounding box (NW 39.04, −107.129; SE 38.814,
  −106.877), which is not a per-site coordinate and is not used.
- The citation references a companion location release
  (doi:10.15485/1618130, "Locations, Metadata, and Species Cover …") that would
  resolve `SampleSiteCode` to coordinates, but it is **not supplied in this
  workspace** and must not be retrieved externally.
- Per Location Resolution Priority Order step 5, coordinates are unresolvable:
  every `site_id` is emitted in the location file with empty `latitude`/
  `longitude` and `qc_flag = g2` (425 sites).

## Depth approximation flag (d1)

Depth is approximated from the reported 2.5–7.5 cm range (midpoint 0.05 m).
Conceptually this warrants `d1` ("depth approximated from a reported range").
The harmonized CSV schema in this project carries no per-row `qc_flag` column
(only the location file does), so the d1 rationale is documented here and in the
mapping entry's depth transformation rather than as a data-row flag.
