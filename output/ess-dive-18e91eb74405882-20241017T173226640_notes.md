# Harmonization notes — dataset 6

- **Dataset identifier:** `ess-dive-18e91eb74405882-20241017T173226640`
- **Canonical index (from MANIFEST.json):** 6
- **DOI:** doi:10.15485/1909712
- **Title:** Raw soil carbon dioxide, moisture, temperature and micrometeorological
  data in the East River Watershed, Colorado June 2021-June 2024 (Snodgrass Mountain).

## Inclusion decision

**INCLUDE.** The package contains direct, in-situ volumetric water content (VWC)
observations from Campbell Sci. CS655 soil moisture probes at three depths
(5, 15, 50 cm) across four tripod stations. This satisfies RULE 2 (direct VWC
observations). No experimental manipulation (RULE 3): the sites are a natural
elevation / forest-type gradient, not a warming/irrigation/drought treatment.
A machine-readable CSV payload is present (RULE 4), and per-site coordinates are
embedded in the payload (RULE 5).

## Payload identification

Only one file is staged in `inputs/raw/`: `Snodgrass_ESS.csv`. It is both the
measurement payload and the location source (coordinates are per-row columns).
The cached ESS-DIVE metadata lists a newer version (`Snodgrass_ess_vers3.csv`)
that is **not** staged; per the run contract, only the staged file was used and
no external retrieval was attempted.

## Structure and transforms

- File has 3 header lines: a machine column header, a human descriptor row, and a
  units row. Rows 2 and 3 (`skiprows=[1,2]`) were dropped before parsing.
- **Wide-to-long:** VWC columns `VWC_5cm`, `VWC_15cm`, `VWC_50cm` were melted to a
  long table; `depth_m` extracted from the column name and divided by 100 (cm→m),
  yielding depths 0.05, 0.15, 0.50 m.
- **Units:** VWC source units are `m3/m3` (units row); no conversion. Observed
  range ~0.02–0.54 is consistent with volumetric fraction, confirming no %→fraction
  division is needed.
- **Missing values:** empty/`NA` strings and `-9999` sentinels coerced to NaN.
  156 VWC values are missing in the long output.
- `replicate = 1` (single sensor per site+depth), `is_timeseries = True`
  (continuous 30-minute logger output, ~206k rows per site over 2021–2024).
- GWC and water potential are not measured → NaN.

## Timezone decision (open question)

There is a conflict in the source:
- The data file's **descriptor row** labels `TIMESTAMP` as `date_time "UTC"`.
- The package **measurementTechnique** metadata says sensors were "logged at
  continuous 30-minute intervals in Mountain Standard Time."

The in-file descriptor was treated as authoritative and timestamps were emitted
as UTC with **no** local→UTC conversion. If the metadata is correct instead,
every timestamp would need a +7 h shift (MST = UTC−7). This ambiguity is flagged
for operator review. Exemplar East River datasets (e.g. dataset 7, 8) treat local
time as `Etc/GMT+7`, but those files did not self-label as UTC; this file does.

## Location resolution

Coordinates resolved from **priority 1 (data payload)**: each row carries
`latitude`/`longitude`. One row per distinct `site_id` emitted. All four sites
resolved, so `qc_flag` is empty (null) for every site:

| site_id | latitude | longitude |
|---|---|---|
| high_conifer | 38.931421 | -106.98524 |
| low_aspen | 38.926196 | -106.97144 |
| middle_aspen | 38.928400 | -106.97812 |
| middle_conifer | 38.927448 | -106.97852 |

These fall within the metadata `spatialCoverage` bounding box
(NW 38.94781/-106.9865, SE 38.92084/-106.9633), providing an independent sanity
check. A small number of late rows had site labels with blank coordinates; the
per-site "first non-null" selection recovered the correct coordinates from
earlier rows for those same sites.
