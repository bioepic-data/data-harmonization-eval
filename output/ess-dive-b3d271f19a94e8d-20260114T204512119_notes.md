| Source | Destination | Notes |
|---|---|---|
| `TIMESTAMP_START` | `datetime_UTC` | Parsed `%Y-%m-%d %H:%M:%S`, local UTC-7 → UTC |
| filename `{SITE_ID}` token | `site_id` | e.g. `ER-PHS1` |

| `SWP_1_1_1` (kPa) | `water_potential_kPa` | already negative kPa |

- **Depth encoding:** Depth is **not** in the data columns. Each SWC column
  `SWC_1_V_1` (V = vertical position 1–4) and SWP column `SWP_1_1_1` is mapped
  to its installation depth from `metadata_instrument_v1-1.csv` `HEIGHT`
  (negative = below surface; depth = |HEIGHT|). HEIGHT is stable per
  (SITE_ID, VARIABLE). Resulting depths: 0.1, 0.3, 0.5, 0.6, 0.75, 1.06,
  1.15 m. SWP is at 0.3 m for all sites.
- **Site availability:** SG-EHS6 and SG-EHS7 lack the deepest SWC
  (`SWC_1_4_1`) column, consistent with the package description.
- **Replicate:** The positional qualifier `H_V_R` has R=1 for all SWC/SWP
  columns (no co-located replicate sensors), so `replicate = 1`.

## Units & missing-value handling

- SWC reported in **percent** (observed range ~11–47%) → divided by 100 to
  m³ m⁻³ (harmonized range ~0.07–0.52).
- SWP reported in **kPa**, already negative; no conversion.
- Numeric missing code `-9999` removed from SWC.
- SWP missing code is **+9999** (positive, because valid SWP is negative), per
  the package description; removed before harmonization.

## Open questions / flags for operator review

1. **SWP sensor-floor values.** The package QA/QC notes state SWP is clamped at
   a minimum valid value of **-2000 kPa** (SG-EHS5/6) or **-99999 kPa** (other
   sites). The harmonized SWP minimum is -99999 kPa; ~34% of SWP values are
   ≤ -2000 kPa and the 1st-percentile is -99999. These appear to be retained
   sensor-limit (very-dry) readings rather than a missing code, so they were
   kept as-is. An operator may wish to treat the -99999 floor values as
   out-of-range and mask them.
2. **Timezone.** Site metadata reports a fixed `UTC_OFFSET = -7` for all sites
   (no DST), so `Etc/GMT+7` (UTC-7) was used rather than `America/Denver`. The
   package notes mention occasional logger DST/clock glitches that were
   corrected by the data producer; residual timestamp uncertainty is possible
   but not resolvable here.
3. **Depth values 0.5 / 0.75 / 1.06 m** differ from the nominal
   0.1/0.3/0.6/1.15 m design at some sites (SG-EHS7 `SWC_1_3_1` = -0.5 m,
   SG-EHS8 `SWC_1_4_1` = -0.75 m, ER-PHS4 `SWC_1_4_1` = -1.06 m). These are the
   as-installed depths from the instrument metadata and were used verbatim; no
   `d1` approximation flag was set because depths are explicitly reported, not
   approximated from a range.
