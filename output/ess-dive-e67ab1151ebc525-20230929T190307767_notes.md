**DOI:** doi:10.6084/M9.FIGSHARE.7834406.V2
**Title:** Raw soil carbon dioxide, moisture, and temperature data from a mixed
conifer and aspen forest stands in the East River Watershed of Colorado, June
2011 – December 2021.

## Decision: INCLUDE

The package contains direct observations of volumetric water content (VWC) from
Decagon Devices 5TE soil moisture/temperature probes installed in two
instrumented soil pits (one mixed-conifer, one aspen/deciduous) at 5, 15, and
50 cm depth, logged hourly. This satisfies RULE 2 (direct VWC observation) and
RULE 4 (machine-readable, time-stamped payload). No duplicate/superseded or
manipulation concerns apply (RULE 1, RULE 3).

## Payload identification

- `Carbone_aspen.csv` — payload (aspen/deciduous pit). Headerless; 79,025 data
  rows, 24 columns.
- `Carbone_conifer.csv` — payload (mixed-conifer pit). Carries an inline header
  row; 79,024 data rows, 24 columns, identical column order to the aspen file.
- `Carbone_headers.csv` — described in the package metadata as a shared headers
  file, but **not staged in `inputs/raw/`**. Not required: the conifer file's
  inline header supplies the column names, which are reused for the headerless
  aspen file (verified identical column count and structure). Limitation
  recorded here rather than retrieved externally.

Relevant columns used: `Year`, `Month`, `Day`, `Hour`, `VWC-50cm`, `VWC-15cm`,
`VWC-5cm`. Non-moisture columns (CO2, temperature, EC, battery voltage) are not
mapped to the target schema.

VWC value ranges confirmed fractional (mostly 0–0.6), so **no %→fraction
conversion** was applied. A small number of out-of-range outliers exist in the
raw data (e.g., one aspen `VWC-5cm` value ~4.19, one slightly negative
`VWC-50cm`); these are retained as-is to avoid fabricating QA decisions beyond
the source's own QA/QC.

## Time series determination

`is_timeseries = True`. The metadata and methods describe a continuous hourly
logger deployment (5TE probes on a data logger), with many observations per
site+depth at regular timestamps.

## Location resolution

Coordinates are **not** present in the payload files and no ancillary location
file is staged. Per the Section 5 fallback hierarchy, coordinates were taken
from source 3 — the package-level ESS-DIVE metadata record
(`spatialCoverage.geo`): **38.9592° N, 106.9898° W** (stored as longitude
−106.9898). The metadata states both soil pits are within 15 m of each other
and reports a single coordinate, so the same lat/lon is assigned to both
`site_id`s.

`qc_flag` is left empty (None) for both sites: coordinates were resolved from
the package metadata record (not from an approved location registry, which
would be `g1`, and not unresolved, which would be `g2`).

## Timestamp / DST handling

Local timestamps are America/Denver (Mountain Time). Daylight-saving
transitions produce two edge cases:

- **Spring-forward (nonexistent) 02:00 hours** → shifted forward (resolved).
- **Fall-back (ambiguous) 01:00 hours** → cannot be unambiguously localized and
  are set to `NaT`; their VWC values are still retained.

Additionally, 72 rows in the conifer file have missing/unparseable date
components in the raw data. In total, 90 unique source rows (× 3 depths = 270
long-format rows) have `NaT` `datetime_UTC` while retaining VWC. This is an
inherent limitation of the source (no UTC offset recorded, standard-time
logging ambiguity) and is documented rather than guessed.
